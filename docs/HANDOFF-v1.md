# 交接任务：wf-agent-workflow 四个纯内核模块

版本：v1
日期：2026-10-27
接收方：外部开发者（使用 Claude Code Haha GUI + agent）

---

## 0. 一句话

你负责四个**纯内核模块**：`ledger`、`render-prompt`、`gates`、`panel`。

它们不联网、不调第三方工具、不需要 API key、不执行管线。

---

## 1. 项目背景

这是一个 Claude Code 工作流插件：

```text
普通模式：原版提示词/工具/行为，仅移除 Workflow
工作流模式：用户显式 /wf 进入，加载另一套提示词与工具权限
```

完整计划见：

```text
project/tool/docs/FINAL-PLAN-V2.md
project/workflow/wf-mode/PRINCIPLES.md
```

你的四个模块是插件内核的一部分，负责：

- 把运行结果写进账本；
- 把配置和提示词块拼成 agent 正文；
- 在交付前校验证据；
- 提供一个本地面板查看/编辑配置。

## 3. 四个模块的共同底线

| # | 底线 | 含义 |
|---|---|---|
| B-01 | 输入输出封闭 | 只接受声明的 JSON/文件，只输出声明的文件/JSON |
| B-02 | 无外部依赖 | 不联网、不调第三方工具、不需要 API key |
| B-03 | 写入面封闭 | 只能写声明的目录与文件名，拒绝路径穿越 |
| B-04 | 失败即拒绝 | 校验失败/写入失败 → 不产出部分结果，fail closed |
| B-05 | 不造数据 | 只做转换、校验、渲染；不发明事实、不补结论 |
| B-06 | 不执行管线 | 不调用 `wf-run`、不触发 pipeline、不调适配器 |
| B-07 | 不留密钥 | 不读取、不打印、不写入密钥；只判断 env 是否存在 |
| B-08 | 确定性 | 同输入同输出；顺序稳定 |
| B-09 | 可测试 | 提供 fixtures + 正例/负例/失败注入 |
| B-10 | 可版本化 | 每个模块有 `version`；输出带 `schemaVersion` |
| B-11 | 不自动修复/安装 | 不自动补字段、不自动装依赖、不改普通配置 |
| B-12 | 错误可归因 | 错误有模块、动作、文件、字段、错误码 |

## 4. ledger

### 4.1 职责

把一次运行的结果落盘：

```text
run.json
evidence.json
result.md
```

### 4.2 输入

```json
{
  "schemaVersion": "1",
  "pipeline": "wf-retrieval",
  "mode": "verify",
  "status": "complete|partial|blocked",
  "summary": ["结论摘要"],
  "evidence": {
    "items": [],
    "limitations": [],
    "gaps": []
  },
  "degradation": []
}
```

### 4.3 程序自动补

```text
runId
runDir
startedAt
finishedAt
toolCalls
usage
```

agent 不提供这些；程序从运行时获取。

### 4.4 输出

```text
run.json       输入 + 自动字段 + schemaVersion
evidence.json  输入.evidence + pipeline/mode
result.md      程序从 summary + evidence 渲染
```

返回：

```json
{"ok": true, "files": ["run.json","evidence.json","result.md"], "errors": []}
```

### 4.5 规则

- 只写 `.wf/runs/<run>/` 下三个固定文件；
- 写入前校验 schema；
- 原子写入：临时文件 + 替换；
- 重复 commit：
  - 同内容 → 幂等成功；
  - 不同内容 → `RUN_ALREADY_COMMITTED`，拒绝覆盖（除非显式 `--replace`）；
- `result.md` 必须由 evidence 渲染，agent 不手写证据表；
- 不判断事实真假；
- 不读账本重做；
- 不写原始网页、不写密钥。

### 4.6 底线

| 必须 | 禁止 |
|---|---|
| 只写三个文件 | 写其它路径 |
| 校验 schema | 自动补字段 |
| 原子写入 | 半文件落盘 |
| 程序生成元数据 | 让 agent 编时间/工具调用 |
| 程序渲染 result.md | 让 agent 重写一遍证据表 |
| fail closed | 写入失败还输出结果 |

### 4.7 验收

- 合法 payload → 三文件正确；
- 缺字段 → 拒绝；
- 路径穿越 → 拒绝；
- 写入失败 → 无半文件；
- 重复 commit → 幂等或明确拒绝；
- result.md 与 evidence 一致；
- 无密钥。

## 5. render-prompt

### 5.1 职责

把配置和提示词块拼成 agent 的最终提示词文件。

### 5.2 输入

```text
pipeline.yaml
prompt-blocks/core.md
prompt-blocks/domain/<mode>.md
prompt-blocks/output/<mode>.md
prompt-blocks/tools/<slot>.md
```

### 5.3 输出

```text
agents/<pipeline>.md
```

或检查结果：

```json
{"ok": true, "changed": [], "errors": []}
```

### 5.4 规则

- frontmatter 的 `tools`/hooks 由 manifest 决定；
- 正文按固定顺序拼接；
- 生成文件带标记：`<!-- generated by render-prompt; do not edit -->`；
- 未知槽位、缺 block → 报错；
- `--check`：生成结果与现有文件比较，漂移即失败；
- `--write`：先备份，再原子写入；
- 只写 `agents/`；
- 不做全局 skill 注册；
- 不手写工具名。

### 5.5 底线

| 必须 | 禁止 |
|---|---|
| 单一正文来源 | 手改生成后的 agent |
| 由 manifest 决定 tools | 手写工具白名单 |
| 缺 block 报错 | 静默跳过 |
| 漂移检查失败 | 带病发布 |
| 写前备份 | 直接覆盖 |
| 只写 agents/ | 写 pipelines/prompt-blocks |

### 5.6 验收

- 生成结果与快照一致；
- 改 block 后 `--check` 失败；
- 缺 block/未知槽位报错；
- `--write` 有备份；
- 不修改其它文件；
- 生成文件无手写工具名。

## 6. gates

### 6.1 职责

在交付前检查证据和格式是否合格。

### 6.2 输入

```text
run.json
evidence.json
gate 列表
```

### 6.3 输出

```json
{
  "ok": false,
  "errors": [
    {"gate": "evidence", "code": "MISSING_SOURCE", "message": "E2 缺来源", "path": "items[1]"}
  ]
}
```

### 6.4 gate 清单

| gate | 检查 |
|---|---|
| `ledger-schema` | 必需字段、类型、枚举 |
| `evidence` | 条目 ID 唯一、状态合法、verified 有来源 |
| `source-tier` | 一手优先；外部 URL 有日期 |
| `file-line` | reading/analyze 断言有 `file:line` |
| `license` | reuse/eval 有许可或明确未知 |
| `security` | 高风险漏洞/未知许可显式接受或阻断 |
| `budget` | toolCalls/费用不超预算 |
| `approval` | write/deploy 有批准 |

### 6.5 规则

- 纯函数：输入 JSON → 输出结果；
- 不读网络、不调工具；
- 不修改数据；
- 未知 gate → 报错；
- 错误顺序稳定；
- 不自动修复。

### 6.6 底线

| 必须 | 禁止 |
|---|---|
| 只做校验 | 自动补证据 |
| 错误可定位 | 只回“失败” |
| 未知 gate 报错 | 静默忽略 |
| 确定性 | 依赖外部状态 |
| 不写文件 | 修改账本 |

### 6.7 验收

- 每个 gate 正例/负例；
- 缺来源 → 失败；
- 缺 file:line → 失败；
- 未知 gate → 失败；
- 通过后不改数据。

## 7. panel

### 7.1 职责

本地 Streamlit 应用：读配置、展示能力、编辑配置、查看待注册工具与健康状态。

### 7.2 内部三层

```text
panel/app.py           只做 UI
panel/data_source.py   只读配置 → ViewModel
panel/actions.py       校验 + 备份 + 写配置 + 调 render
panel/view_models.py   UI 只认识这些结构
```

### 7.3 ViewModel

```python
PipelineView(id, modes, min_tools, slots, gates, write_surface, approval)
AdapterView(slot, adapter, status, license, os, health, quota, credentials_present)
PendingToolView(slot, tool, register_url, env_names, quota, card_required, status, alternatives)
HealthView(slots, adapters, degraded, missing)
SpecView(expectation_spec, work_order, decisions)
```

### 7.4 允许写入

```text
pipelines/*.yaml
prompt-blocks/*
panel/data/pending-tools.yaml
panel/data/health.json
```

不写：

```text
agents/（由 render-prompt 生成）
normal config
ledger
tools/adapters
secrets
```

### 7.5 面板功能

必须包含：

1. 管线/模式列表与编辑；
2. 提示词块编辑与预览；
3. 工具流程编辑：槽位、主备、actions、minTools；
4. 待注册工具清单：URL、env 名、额度、是否要卡、状态；
5. 能力矩阵：管线×模式×槽位×适配器×健康×额度×许可；
6. 索引层页面：Expectation Spec、Work Order、Catalog、Recommendation、Decision Ledger；
7. 健康与渲染检查；
8. 保存前 schema 校验、备份、保存后调 `render-prompt --write`。

如果实现遇到阻塞，允许先交只读版本（1、4、5、7），并在交付说明中写清未完成项。

### 7.6 规则

- 保存前 schema 校验；
- 保存前备份；
- YAML 写入策略先定：规范化写入，或用 `ruamel.yaml` 保留注释；
- 保存后调 `render-prompt --write`；
- 只显示 env 是否存在，不显示值；
- 不执行管线；
- 不自动安装依赖；
- 不改普通模式配置；
- 面板崩溃不影响 Kernel。

### 7.7 底线

| 必须 | 禁止 |
|---|---|
| 只读配置/写允许路径 | 写普通配置 |
| schema + 备份 | 直接覆盖 |
| 不显示密钥 | 读取/打印密钥值 |
| 不执行管线 | 触发 wf-run |
| 失败不影响内核 | 改共享状态 |
| 使用 ViewModel | UI 直接读 YAML |

### 7.8 验收

- `streamlit run` 健康端点 200；
- fixtures 渲染正确；
- 待注册清单正确；
- 保存非法配置被拒；
- 保存前有备份；
- 保存后调 render；
- 不显示密钥；
- 不执行管线；
- 面板崩溃不改变配置。

## 9. 环境与可能遇到的问题

### 环境

- Windows 11；
- Python 3.12；
- Node.js 20+（面板不需要）；
- 无 Linux/Docker；
- Streamlit 需要安装。

建议：

```bash
python -m venv .venv
.venv\Scripts\activate
pip install pyyaml jsonschema streamlit
# 可选：pip install ruamel.yaml
```

运行模块测试不需要 API key。

### 可能遇到的问题

1. **API key 不可用**
   你的四个模块不需要任何 API key。不要向我们要 key，也不要读取我们的环境变量。

2. **Claude Code Haha 配置**
   你使用自己的 GUI/Provider 配置；交接包**不包含** `cc-haha/`、`.claude.json`、sessions、logs、备份。不要复制我们的配置。

3. **绝对路径**
   `launch.ps1` 和 `agents/*.md` 的 hook 路径写的是我们的 D 盘路径。你的模块测试不要依赖它们；若要跑完整工作流，自己改本机路径并记录。

4. **中文用户名/GBK**
   控制台可能按 GBK 解码，导致中文输出乱码或报错。统一 UTF-8：
   - Python 文件读写显式 `encoding="utf-8"`；
   - 子进程设 `PYTHONUTF8=1`；
   - 不要依赖控制台默认编码。

5. **YAML 注释**
   直接写 YAML 会丢注释。先决定：
   - 规范化写入，不保留注释；
   - 或用 `ruamel.yaml` 保留注释。
   在 README 写清选择。

6. **Streamlit 首次安装超时**
   可能网络超时；重试即可，不是兼容性问题。

7. **不要执行管线**
   你的模块不能调用 `wf-run`，不能触发 pipeline，不能调适配器。面板只读/写配置。

8. **不要写共享文件**
   `registry.yaml` 主文件、`agents/`、`pipelines/`、`prompt-blocks/` 的修改要按你的模块职责来；测试阶段用 `fixtures/`，不要改项目真实配置。

9. **不要存密钥**
   面板只显示环境变量是否存在，不显示值；日志、测试输出、交付文档不得出现密钥。

10. **提交失败/半文件**
    ledger 必须原子写；失败时不留下半成品。

## 11. 验收与合并

你交付后，我们会：

1. 在独立副本运行你的测试；
2. 用 `fixtures/` 验收；
3. 检查写入面、密钥、路径；
4. 通过后按模块合并；
5. 失败时返回具体失败清单，不合并半成品。

验收命令示例：

