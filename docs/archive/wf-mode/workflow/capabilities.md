# 能力槽基线（维护用）

最后校准：2026-10-25。

本文件只记录“某类能力当前由什么填充”，不记录具体项目名单的永久承诺。管线规范只引用能力槽 ID。

## 失效规则（优先于表格本身）

- 表中任何“可用”通道突然失败 → 第一假设是**本表过期**，立刻重测该通道并回写本表＋改校准日期。
- 一次失败不许断言“该能力不存在”，也不许为了绕过失败去换姿势触碰安全层。
- 被权限分类器拒绝（非能力故障）→ 即停、报告、不重试。
- 用户说“能用”而表里写“不可用” → 以用户为准，重测后回写。

## 槽位表

| 槽位 | 用途 | 当前填充 | 状态 | 降级档 | 发现规则 |
|---|---|---|---|---|---|
| `source_discovery` | 发现新来源/项目 | 无搜索工具 | ❌ 不可用 | 只使用用户给定来源；列“来源发现受限” | 运行时检查是否有搜索类 MCP/插件；不引用历史名单 |
| `page_fetch` | 读取网页正文 | `WebFetch` | ✅ 内置工具 | 本地副本 → 用户给定文件 → `blocked` | 每次实调一次确认返回正文，不采信“已启用” |
| `repo_meta` | 仓库元数据与活跃度 | GitHub API + 只读 git | ⚠️ 非封装 | 仅元数据并降低结论强度 | 优先仓库类 MCP；不可用时才走 API/只读 git |
| `repo_read` | 读代码结构 | `Read/Grep/Glob` | ✅ 内置工具 | 只能扫描并在 `uncovered` 标注覆盖不足 | 代码索引/LSP 类工具优先 |
| `workspace_search` | 工作目录检索 | `Grep/Glob` | ✅ 内置工具 | 逐目录扫描并标注覆盖不足 | 工作区搜索类封装优先 |
| `artifact_write` | 写运行账本 | `Write` + hook 限定路径 | ✅ 受控 | 不写盘则拒绝交付（当前不允许） | 仅 `Write`，路径由 hook 强制 |
| `run_control` | 长任务断点/重入 | `run.json` 状态字段 | ⚠️ 仅预留 | 单趟闭环 | P5 再设计 |

## 引入协议（每个槽、每个候选都走一遍）

1. **发现**：按能力找候选，不按名字清单找。
2. **实测**：真实调用一次，拿到业务返回值；“在列表里/已启用/文件存在”都不算。
3. **留档**：回写本表的“当前填充 / 状态 / 降级档”和校准日期。
4. **接线**：只改适配层与管线 prompt 的工具引用，不改阶段结构。
5. **失效**：任一“可用”突然失败 → 按上面的失效规则处理。

## 引入优先级

1. `page_fetch`：检索与评估都依赖。
2. `repo_meta`：降低 eval 对 git clone 的依赖。
3. `source_discovery`：没有它，检索取证只能做“给定来源核验”。
4. `workspace_search` / `repo_read`：增强覆盖度。
5. `run_control`：长任务循环的前置。

## 记录格式（新增通道时追加一行）

```text

填充：
状态：✅ / ⚠️ / ❌

降级档：
失效表现：
```
