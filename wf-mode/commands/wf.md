## 硬边界

- 本命令只允许 `wf_stage.py calibrate`；没有调研工具、没有 GitHub/Web MCP、没有写文件工具。
- 不得调用 `wf-tool.py call`、`web_search`、`web_extract`、`project_search`、`repo_ingest`、`structural_search`、`dependency_graph`。
- 不写文件、不建目录、不安装依赖、不部署。
- 闸口 1 的确认方式是：用户确认需求后，**由用户手动运行 `/wf-plan`**。你不得自行进入调研。
- `calibrate` 会尽力启动并自动打开配置面板；这是面板运行时产物，不属于工作流记录，也不要向用户展示其 JSON。

## 阶段 1：能力校准

说明“正在校准可用能力并打开配置面板”，然后运行：

```bash
python "{{WF_ROOT}}/tools/wf_stage.py" calibrate
```

命令输出只在内部使用，不要原样贴给用户。用一句话汇总：哪些能力可用、哪些降级/缺失/待接入；缺失项写进后续“未知项/缺口”，不要假装可用。

## 阶段 2：需求理解

说明“正在理解任务并做最小取证”。

- 只做确认任务所需的最小读取：Read/Grep/Glob。
- 不调用任何外部调研能力，不做候选调研，不给方案。
- 用 Markdown 列表直接输出需求，不使用代码块，控制在 10 行内；只写功能性内容，不提文件名、路径或自造术语：

任务：<任务原文>
交付：<用户最终拿到的结果>
必须做到：
- <可观察、可验收的行为>
不做：
- <边界与非目标>
验收：<判断完成的标准>
不确定：<默认假设与待确认项>

规则：

- “必须做到”与验收标准要可观察、可验收，不写“好用”“高质量”这类无法验收的词。
- 信息不足时给出默认假设并列入“不确定”，不要连续追问。
- 没有可靠来源的内容标为“未核实”，不要写成事实。

## 阶段 3：闸口 1（需求确认）

输出需求后，调用 `AskUserQuestion`：

- header：`需求确认`
- question：`以上需求是否准确？确认后请手动运行 /wf-plan 进入调研。`
- options：
  1. `确认需求` — 我会停止本轮，并提示你手动运行 `/wf-plan`。
  2. `修正需求` — 在 Other 中写明要改的内容；我会更新后再次确认。
  3. `终止` — 停止本次 wf，不继续调研。

处理结果：

- 用户选“确认需求” → 只输出下面的提示并结束本轮，不调用任何工具：

```text
需求已确认。本命令没有调研工具，下一步请手动运行：

/wf-plan

以上需求会通过对话上下文传递给下一阶段。
```

- 用户选“修正需求” → 读取用户补充内容，更新需求，回到阶段 2 重新取证；最多 3 轮。
- 用户选“终止” → 输出“已终止，未进行调研”，结束。
- 用户没有明确确认时，不得推进，也不得自行运行 `/wf-plan`。

如果 `AskUserQuestion` 不可用：用纯文本提出同样的问题并停止本轮，不自动继续。
