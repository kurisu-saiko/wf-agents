# 本工作流的最高原则（优化前必读）

> 任何对本工作流的修改、重构、工具接入、提示词优化，必须先对照这五条。
> 与这五条冲突的方案，先停下讨论，不得直接实施。

## 1. 组装优先

管线的核心工作是使用和组装现成的项目、API、技能、工具，尽量不亲自写代码造产物。工具以薄适配器形态存在：内部调 API 或其他实现，对外只暴露一个命令或工具；能力槽位化、可插拔，底层命令只作降级档。换工具不改管线结构。

## 2. 可复现的单趟流程

目标是可复现的工程化产出，不是模型临场发挥。同一类输入走同一条路径；结果可以不同，流程必须一致。一次管线 = 一次回复，中途不重入；证据不足只能作为终态输出。

## 3. 双轨隔离

普通模式保持原版提示词、原版工具、原版行为，仅移除 `Workflow`；工作流模式加载另一套提示词与工具权限，两套互不影响。wf 资产放在独立配置和独立进程里；正常配置只保留唯一入口 `commands/wf.md` 并禁用 `Workflow`，agents/workflows/skills 中没有 `wf-*`。入口必须由用户显式触发。

## 4. 隔离靠结构，不靠提示词自觉

代理正文就是该层提示词；`tools` 是物理工具白名单，管线之间工具互不可见。每个 `wf-*` 代理自带 agent 级 `PreToolUse` hook，普通模式完全没有这些 hook；越界工具、路径、命令由 hook 拒绝。规范不做全局 skill 注册，因为全局注册无法同时满足“只绑定指定 agent”和“主会话不可见”；规范源只作维护源，装配时写进 agent 正文。

## 5. 人对齐与授权

方案先对齐再动手；破坏性、不可逆、影响共享状态的动作先确认；凭据、账号、配置归用户，不擅自生成、修改或回显。

---

## 一句话

用现成能力组装，用固定流程保证复现，用双轨与结构强制保证隔离，用单趟终态保证确定性，用人工对齐守住不可逆边界。
